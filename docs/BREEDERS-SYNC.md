# 브리더 목록과 유충 양방향 편집

홈, 성충 표, 개체 상세, 계통도, 라인 카드, 댓글, 프로필 영역의 브리더 사진·이름은 `#/breeder/<회원ID>`로 이동합니다. 프로필에는 이미 승인 회원에게 공개된 닉네임·사진과 KML 기록만 표시하며 이메일·인증 정보는 조회하지 않습니다. 성충은 보유 성충/브리딩 성충으로 나눠 선택할 수 있고, 해당 회원이 등록한 라인도 함께 표시합니다.

라인 유충 표와 유충 상세의 **기록 수정**은 라인 등록자와 관리자만 사용할 수 있습니다. 관리번호, 성별, 상태, 메모, 모든 병의 날짜·먹이원·종류·용량·무게·두폭·다음 교체일·령수·메모·푸딩 여부, 전용·용화·우화 정보를 수정합니다. 병 추가·제거 시 원본 병 ID로 나머지 병의 사진·플래그 등 추가 정보를 보존합니다. 0과 빈 값은 구분합니다. 사진 자체의 교체는 BeetleLog에서 합니다.

## DB 설치 및 동작

`docs/larva-bidirectional-sync.sql`을 프로젝트 소유자 권한으로 한 번 적용합니다. `kml_internal` 비공개 트리거가 `kml_larvae`와 `beetlelog_data.data.individuals`를 연결합니다. 기존 자료를 설치 시 덮어쓰지 않습니다. KML 저장은 유충의 `updated_at` 조건으로 충돌을 감지합니다. 동기화 대상이 없으면 KML 저장도 함께 실패하여 분리된 기록이 생기지 않게 합니다. 연결 ID·소유자·라인은 클라이언트 수정 권한에서 제외합니다.

BeetleLog에서 이미 연결된 라인에 새 유충을 추가하면 KML에도 등록됩니다. 삭제와 연결되지 않은 라인으로 이동은 다른 앱의 기록을 삭제하지 않습니다. KML에서 새로 만든 유충을 BeetleLog로 내보내는 기능은 포함하지 않습니다. 기존 연결 없이 다른 회원의 개인 BeetleLog 자료를 편집하지 않습니다.

`docs/beetlelog-linked-upload-guard.sql`은 구버전 BeetleLog의 업로드 RPC도 유충을 보호하도록 보완합니다. 최신 BeetleLog는 마지막 서버 스냅샷을 기준으로 세 방향 병합을 하고, 서버 버전 조건으로 저장합니다. 서로 다른 항목은 병합하고 같은 항목의 상충 변경은 저장을 중단하며 기기 기록을 유지합니다. 서버 스냅샷은 기기에 보관하여 오프라인 수정도 다음 실행에서 비교합니다.

두 앱은 편집 중에는 갱신하지 않고, 활성 상태에서 약 8초 주기 및 포커스 복귀 시 최신 기록을 확인합니다. 네트워크가 없으면 서버 반영은 완료되지 않습니다. 앱을 오래 열어 두었다면 새로고침해 최신 코드를 적용합니다.

## 검증

- `node tests/breeders-larva-editor.cjs`: 회원별 조회 범위, 링크, 소유자 편집, ID·추가 정보·0 보존, 입력 검증
- BeetleLog `node tests/cloud-sync.cjs`: 다른 항목 병합, 동시 저장 재시도, 같은 항목 충돌, 삭제/추가와 원본 보존
- `tests/larva-bidirectional-sync.sql`: 실제 DB에서 인증·RLS를 적용해 양방향 수정, 새 유충, 구버전 업로드 방어, 충돌과 권한을 검증하고 전체 롤백

계통도·연도·라벨·가져오기 기존 회귀 검사와 BeetleLog 전체 JSX 변환도 확인했습니다. 아이폰·안드로이드 실기기에서 터치·편집 화면을 직접 검증한 결과는 아닙니다.
